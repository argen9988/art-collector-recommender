# 2026-10 決策紀錄

## D1（2026-10-28）：維持 Google AI Studio（Paid Tier 付費層），不遷移至 Vertex AI

- **背景**：初期評估曾建議正式環境由 Google AI Studio 遷移至企業級 Vertex AI 以免除靜態 API Key 並強制台灣機房落地。
- **決策**：修正為**維持 Google AI Studio（Paid Tier 付費層）＋ 後端 Secret Manager 環境變數隔離**，將 Vertex AI 列為未來跨部門擴編時之選配項（暫不執行）。
- **理由**：
  1. 只要在 Google AI Studio 綁定 Cloud Billing 進入 Paid Tier，Google 合約即承諾 100% 不將客戶資料用於模型訓練，已解決最核心的資安隱私風險。
  2. 遷移至 Vertex AI 會破壞 AI Studio 內建預覽與一鍵部署的相容性，對關係企業獨立運作、無專職雲端工程師的小規模部門工具而言維護負擔過高。

## D2（2026-10-28）：關係企業獨立運作與無企業網域之輕量化治理模式

- **背景**：本單位屬於關係企業獨立於母公司運作，且同仁使用一般 `@gmail.com` 帳號登入（無企業專屬 Workspace 網域），過去採主管信用卡每次儲值 NT$1,000 模式。
- **決策**：
  1. 以「部門公務專用 Gmail ＋ 主管 Gmail」共同擔任 GCP 專案 `Owner`（至少 2 人互為備援），不需申請複雜的母公司 GCP Organization。
  2. 透過「每月 NT$1,000 預算警示（軟止損）＋ Gemini API 每日 1,000 次請求配額上限（硬止損）」雙重保險，防止後付制帳單失控。
  3. 透過 GCP OAuth Consent Screen 維持 `Testing` 模式並將部門同仁 Gmail 列入 `Test users` 白名單（搭配後端 `ALLOWED_EMAILS` 檢查），在無企業網域下達成 100% 阻絕外部 Gmail 登入。

## D10（2026-10-30）：3-3 網址預檢、3-4 MDN Observatory 的做法與 findings 欄位

## D11（2026-10-30）：審閱段 D1 後調整 3-3、3-4 的判斷與 findings.json 的寫法

- **背景**：commit 2b36b09（D10 的實作）整批審閱，找出誤報、漏報、AI 代跑會卡住、內部主機名稱可能外洩等問題。
- **決策**（D10 其餘照舊）：

  4. 本機的 http 網址不報 Cookie 沒 Secure。

  6. 輸入不是終端機時，讀管線的回答最多等 3 秒，等不到就當沒回答（3-4 不送、3-2 改跑本機模擬）；管線回答 y 的用法保留。審閱時建議的「非終端機又沒帶 `--observatory` 就直接不送、不讀輸入」沒採用：會拿掉管線回答 y，3-2 的同一個問題也不會一起修好。

## D13（2026-10-30）：3-5 Artifact Analysis 的做法——自動掃描加「立即掃描」，有修補版本的高、中風險才擋
