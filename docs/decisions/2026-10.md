# 2026-10 決策紀錄

## D1（2026-10-28）：維持 Google AI Studio（Paid Tier 付費層），不遷移至 Vertex AI

- **背景**：初期評估曾建議正式環境由 Google AI Studio 遷移至企業級 Vertex AI 以免除靜態 API Key 並強制台灣機房落地。
- **決策**：修正為**維持 Google AI Studio（Paid Tier 付費層）＋ 後端 Secret Manager 環境變數隔離**，將 Vertex AI 列為未來跨部門擴編時之選配項（暫不執行）。
- **理由**：
  1. 只要在 Google AI Studio 綁定 Cloud Billing 進入 Paid Tier，Google 合約即承諾 100% 不將客戶資料用於模型訓練，已解決最核心的資安隱私風險。
  2. 遷移至 Vertex AI 會破壞 AI Studio 內建預覽與一鍵部署的相容性，對關係企業獨立運作、無專職雲端工程師的小規模部門工具而言維護負擔過高。

## D2（2026-10-28）：關係企業獨立運作與無企業網域之輕量化治理模式

- **背景**：本單位屬於關係企業獨立於母公司運作，且同仁使用一般 `@gmail.com` 帳號登入（無企業專屬 Workspace 網域），過去採主管信用卡每次儲值 NT$1,000 模式。
- **決策**：
  1. 以「部門公務專用 Gmail ＋ 主管 Gmail」共同擔任 GCP 專案 `Owner`（至少 2 人互為備援），不需申請複雜的母公司 GCP Organization。
  2. 透過「每月 NT$1,000 預算警示（軟止損）＋ Gemini API 每日 1,000 次請求配額上限（硬止損）」雙重保險，防止後付制帳單失控。
  3. 透過 GCP OAuth Consent Screen 維持 `Testing` 模式並將部門同仁 Gmail 列入 `Test users` 白名單（搭配後端 `ALLOWED_EMAILS` 檢查），在無企業網域下達成 100% 阻絕外部 Gmail 登入。

## D3（2026-10-28）：Cloud SQL 規格採互動式選擇，增設 NT$500–600/月 甜蜜點方案

- **背景**：Cloud SQL 24 小時連續開機牌價在 `db-f1-micro`（0.6GB RAM，約 NT$300/月）與 `db-g1-small`（1.7GB RAM，約 NT$800/月）之間存在價格斷層，且強制降級為 `db-f1-micro` 未必符合所有執行者對效能或備份的需求。
- **決策**：腳本不強制降級，改為先偵測現況並列出 5 種方案供執行者討論決定，特別加入兩個 **NT$500–600/月** 方案：
  1. **`db-g1-small`（1.7GB RAM）＋ 平日上下班自動啟停排程（08:00–22:00 開機，夜間與週末休眠省 58% 運算費）**：月租約 NT$480～560/月，兼顧大記憶體順暢度與預算。
  2. **`db-f1-micro`（24h 開機）＋ 50GB SSD ＋ 30 天 PITR 時間點還原備份**：月租約 NT$500～580/月，適合全天候不關機且重視大容量備份之情境。

## D4（2026-10-28）：採用方案 C 二合一 Lazy Pack，開場說明流程且所有步驟遵循「先檢查現況、已存在自動跳過」

- **背景**：為降低人工設定遺漏與重複檢查成本，評估如何將雲端資安設定與上線前驗收交由 AI 與腳本自動化。
- **決策**：採用方案 C（`config/params.json` ＋ `lazy-pack/gcp-setup-and-check.sh` ＋ `lazy-pack/code-and-ai-audit.mjs`），在互動流程一開頭先向執行者說明整個 Lazy Pack 要做的事，且所有關卡一律先執行唯讀現況檢查（Pre-check），已存在或已符合標準者自動標記 `✅ 已存在，跳過`。

## D5（2026-10-28）：將「啟用 Vertex AI」與「排程發送客製化 EDM」並列為 Lazy Pack 非必要選配項，並確立三級月租收費套餐

- **背景**：使用者提出補強需求：(1) 互動開頭先說明 Lazy Pack 要做哪些事；(2) 將 Vertex AI 列為選項並加入 Lazy Pack；(3) 系統若需排程設定「以人推畫」或「以畫推人」不定期發送自製 EDM 至藏家信箱，須評估收費方案如何調整，並將【第 8 關：排程發送客製化 EDM 之 Cloud Scheduler API 檢查與啟用】條列說明、與「啟用 Vertex AI」並列為非必要選項（選配項）。
- **決策**：
  1. 於 `gcp-setup-and-check.sh` 將 **Stage 7（啟用 Vertex AI）** 與 **Stage 8（排程發送客製化 EDM 之 Cloud Scheduler API 與 EDM 密鑰）** 並列為 **🟢 非必要選配項目（預設皆為 `[1] 暫不啟用／維持現況跳過`）**；若初期由同仁手動查詢或於畫面手動按鈕寄信，完全不需開啟背景排程。
  2. 選配啟用排程 EDM 時，架構採用 **Cloud Scheduler（每月前 3 個排程免費，NT$0）＋ Cloud Run `/api/cron/send-edm`（驗證 `CRON_SECRET`）＋ Resend / Brevo 外部發信 API（免費版每月 3,000～9,000 封，NT$0）**，並嚴格規定一對一獨立發信（`cc_list` 必為空）、遵守 `edm_daily_send_limit: 100`。
  3. 制定三種含 EDM 之總月租套餐：**套餐 A 極簡版（約 NT$300–380/月）**、**套餐 B 部門推薦甜區版（`db-g1-small` 平日排程 ＋ 免費發信額度，約 NT$500–600/月，注意 EDM 排程須設在資料庫開機時段內）**、**套餐 C 全天候專業行銷版（`db-g1-small` 24h ＋ Resend Pro/Brevo 付費版，約 NT$1,500–1,650/月）**。

## D6（2026-10-29）：導入 `AGENT_SETUP` 跨 AI 代操領航指南、三階段不押日期與細項可選、預算配額互動問答、每月費用精算器與雙軌報告輸出
