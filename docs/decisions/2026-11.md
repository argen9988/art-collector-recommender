## D20（2026-11-02）：Lazy Pack「四步閉環流程」與「四合一透明動作卡（代操不黑箱）」實作規範

- **背景**：在討論針對無資訊背景使用者設計的 Lazy Pack 時，使用者提出核心原則：① 執行流程應為「先用指令檢查現況 ➔ 告知並用指令代操調整 ➔ 無法調整的才列手動步驟 ➔ 複查驗收」；② 即使背後有腳本指令代操，也必須保留詳細說明與隨時可呼叫查看 Console 網頁位置與底層 Shell 指令的機制，確保代操不黑箱，兼顧無腦操作與透明審計。
- **決策**（使用者 2026-11-02 定）：
  1. **四步閉環流程**：未來所有 Lazy Pack 推進標準為：①【唯讀體檢】先跑唯讀指令盤點現況（綠燈跳過/紅燈列出），零風險不擅改；②【白話告知 & 指令代操】白話說明紅燈影響，能用指令解決的經同意由 AI/指令直接代跑，動作前後交代「背後做了什麼」；③【最小手動引導】涉及信用卡、帳密或政策未開放 CLI 者，列 3～5 步圖文點選步驟由使用者親手按；④【複查出報告】再次體檢全綠燈，產出報告與費用精算。
  2. **四合一透明動作卡**：所有細項均包含四大元素：① 🎯 白話說明（做什麼、為什麼、影響與安全性）、② 💻 背後執行的 Shell 指令（透明審計）、③ 🌐 GCP Console 在哪裡改（直達網址 ＋ 繁中介面麵包屑路徑）、④ 👉 雙軌呼叫機制（可隨時依口令切換「幫我指令改」或「教我手動點」或「顯示指令」）。
  3. **落地範圍**：寫入 Jarvis（`ai-companion`）待辦（commit `fc6913f`），全面改寫 `AGENT_SETUP_雲端資安設定與驗收指南.md` 與 `README.md`。
- **取代**：升級原本的「6 點白話說明卡」，擴充為四合一雙軌架構。

## D21（2026-11-02）：細項 2-1 金鑰隔離前置智慧探測（聯動 3-1 靜態掃描）機制定案

- **背景**：在實測第二階段細項 2-1（把 API 金鑰與資料庫密碼收進 Secret Manager）時，使用者提出核心痛點：在未執行第三階段原始碼掃描前，無資訊背景之使用者根本不知道程式碼中寫死了哪些機敏金鑰與資料庫連線字串，亦不清楚變數名稱，手動輸入門檻高且易困惑；若將整包第三階段移到最前，又會因為 Cloud Run/Cloud SQL 尚未部署而導致 3-2～3-5 線上與容器檢測全部連線失敗。
- **決策**（使用者 2026-11-02 同意方案 3）：

## D23（2026-11-02）：資料庫雙軌保留（Cloud SQL / Firestore）、程式碼特徵動態預掃與資安驗證標準分流

- **背景**：原 Lazy Pack 僅鎖定 Cloud SQL（關聯式資料庫），每個月有基本實例月租（NT$300～600+）。使用者提出若系統換成 Cloud Firestore / Firebase（Serverless NoSQL，每月有免費 5 萬次讀取額度，月租 NT$0），兩種方案皆須保留，且應由腳本主動偵測程式寫法與雲端資源，自動決定走哪一套驗證與設定方式。
- **決策**（使用者 2026-11-02 確認採納雙軌保留與代碼預掃）：
  1. **雙軌保留與主動偵測機制**：
     - **雲端探測（`gcp-setup-and-check.sh`）**：依序查詢 `gcloud sql instances list` 與 `gcloud firestore databases list`。僅有 Cloud SQL 走 Cloud SQL 軌道；僅有 Firestore 走 Firestore 軌道；兩者皆有或皆無時，印出選單供使用者確認主力資料庫。探測結果存入狀態檔 `SAVED_DB_TYPE`（`cloud_sql` 或 `firestore`）。
     - **程式碼動態預掃（`code-and-ai-audit.mjs`）**：檢查 `package.json` 與程式碼引用特徵，判定架構：
       - **純後端架構（做法 A，最推薦）**：僅依賴 `@google-cloud/firestore` 或 `firebase-admin`，前端組件無直連引用。驗收要求雲端 Firestore Security Rules 阻絕外網直讀（`allow read, write: false;`），無前端洩漏風險。
       - **前端直連架構（做法 B）**：依賴 `firebase` Client SDK 且前端組件直接調用。細項 3-1 白名單放行合規之 `firebaseConfig`（`apiKey`、`projectId` 等），但雲端 Security Rules 嚴禁 `allow read, write: if true;`，且嚴格禁止暴露服務帳戶私鑰或 `GEMINI_API_KEY`。
  2. **資安驗證與設定標準分流**：
     - **Cloud SQL**：維持細項 2-1 密碼入 Secret Manager、2-2 關公網 IP/開 SSL/開備份、2-3 規格 6 選 1 與費用精算（月租 NT$280～880）。
     - **Firestore**：細項 2-1 採 IAM/Admin 憑證授權（不需資料庫密碼）、細項 2-2 檢查 Native 模式/台灣機房/Security Rules/排程備份、細項 2-3 展示 Serverless 免費額度說明並精算資料庫月租為 **NT$0 / 月**。
  3. **落地範圍**：寫入 `docs/decisions/2026-11.md`、更新 `AGENTS.md`、`config/params.json`、`lazy-pack/gcp-setup-and-check.sh`、`lazy-pack/code-and-ai-audit.mjs` 與對應測試。
- **取代**：解決 `docs/todo-plan.md`「改用 Google／Firebase 服務時的檢測差異」待辦。
